# Hostlane 需求文档

> 版本 0.2 · 2026-11-25

## 1. 产品定位

**一句话**：让你自己的 agent（Codex、Claude Code 或自研 agent）在本机安全地操作远程服务器，同时管理服务器上 web 服务的端口和本地端口映射。

Hostlane 只提供“手脚”：连接、执行、读写文件、端口映射和安全管控。“大脑”由外部 agent 提供。

**不做的事**

- 不内置 LLM，不调用任何模型 API。
- 不在服务器上安装任何组件，服务器端只依赖 `sshd`、POSIX shell 和 SFTP。
- 暂不做团队协作和云端同步。
- 暂不支持 Kubernetes。
- 暂不支持人工在终端中输入；终端只用于观察 agent 的操作。

**目标用户**：独立开发者和小团队运维人员。他们管理多台服务器，并使用 agent 完成开发和维护工作。

## 2. 已确定的决策

| 主题 | 决策 |
| --- | --- |
| 名称 | Hostlane；CLI 命令为 `hostlane` |
| 守护进程语言 | Rust（`tokio` + `russh` + `rmcp` + `rusqlite`），重点考虑性能和常驻时的资源占用 |
| 运行方式 | 守护进程 `hostlane daemon` 常驻并注册为用户级服务；Electron 可以完全退出 |
| 桌面端 | 基于 Desktop-Starter（Electron + React + Tailwind + Radix） |
| 人的操作入口 | 主机与凭据、agent 接入、审批、监视、审计导出和回滚必须有图形界面；手工运行 CLI 或编辑 shell 配置不是使用桌面端的前置条件。CLI/MCP 继续作为 agent 的入口 |
| 端口管理范围 | 支持 systemd、Docker 和 docker-compose；不支持 Kubernetes |
| 终端 | 只读会话监视器，实时显示和回放 agent 执行的命令与输出；不支持人工输入或接管 |

## 3. 总体架构

```text
你的 agent ──CLI / MCP──┐
                        ▼
Electron UI ──IPC──► 主进程 ──本地 socket──► hostlane daemon ──SSH/SFTP──► 服务器
                                              ├─ 连接池
                                              ├─ 执行器 / 后台任务
                                              ├─ 文件操作
                                              ├─ 端口映射（隧道）
                                              ├─ 端口发现与服务识别
                                              ├─ 策略引擎 / 审批队列
                                              └─ 审计日志（SQLite）
```

- CLI、MCP 和桌面端连接同一个守护进程，共享连接池、隧道和审批队列。
- 关闭桌面端不影响 agent。需要审批时，守护进程发送系统通知；点击通知后打开桌面端并进入审批页。
- 有图形会话时，守护进程在 macOS 菜单栏、Windows 通知区域或支持 StatusNotifierItem 的 Linux 托盘中显示图标。图标与守护进程同寿命，不表示 SSH 连接状态；使用桌面安装包时可通过图标重新打开窗口。
- SSH 私钥、密码和审计数据只保存在本机。凭据不进入渲染进程，也不写入日志。

详细的目录结构和协议约定见 [architecture.md](architecture.md)。

## 4. 功能需求

优先级：**P0** 是 MVP 必须包含的功能，**P1** 计划在第一个正式版实现，**P2** 后续再做。

### 4.1 主机管理

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| H1 | 导入 `~/.ssh/config`（包括 `Include`），也可以手动添加主机 | P0 |
| H2 | 认证方式支持 `ssh-agent`、密钥文件和密码；密码与密钥口令保存在系统钥匙串 | P0 |
| H3 | 支持跳板机（ProxyJump），包括多级跳板 | P1 |
| H4 | 支持主机分组和标签；环境标签分为 dev、staging、prod | P0 |
| H5 | 显示连接状态和延迟；断线后自动重连 | P0 |
| H6 | 生成主机画像：系统、CPU、内存、磁盘，以及可用工具（`tmux`、`rg`、`docker`、`git`） | P1 |
| H7 | 为每台主机保存备注，并能导出为 Markdown，供 agent 作为上下文使用 | P1 |
| H8 | 首次连接时校验主机指纹；指纹变化时告警并拒绝连接 | P0 |
| H9 | 每台主机可单独开启后台 SSH 可达性检测（默认关闭，每 5 分钟）；界面及 agent 可读取最近结果与时间，与登录状态分别展示 | P1 |

### 4.2 Agent 接入

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| A1 | 提供 `hostlane` CLI：所有能力都有对应命令，并支持 `--json` 输出 | P0 |
| A2 | 提供 MCP Server（`hostlane mcp`，stdio），工具与 CLI 一一对应 | P0 |
| A3 | “接入”页可一键复制 Codex、Claude Code 和 Cursor 的配置片段，也可把 CLI 安装到 PATH | P0 |
| A4 | 返回结构化结果和错误码；长输出只保留头尾，完整内容通过 `output_id` 分页读取 | P0 |
| A5 | 为每个 agent 分配客户端名称和令牌，审计中可以区分调用来源 | P1 |
| A6 | 按客户端限制可访问的主机和能力范围 | P2 |

### 4.3 命令执行

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| E1 | `exec`：可设置工作目录、环境变量和超时；返回退出码、stdout、stderr 和耗时 | P0 |
| E2 | 后台任务：`job_start`、`job_status`、`job_logs`、`job_cancel`；远程有 `tmux` 时使用 `tmux`，否则使用 `nohup` | P1 |
| E3 | 交互式 PTY：agent 可以通过 `pty_open`、`pty_send`、`pty_read` 操作交互程序；人工不能接管 | P2 |
| E4 | `exec_many`：对主机组批量执行，支持设置并发数、先在一台主机上试运行（金丝雀），以及失败时立即停止 | P2 |

### 4.4 会话监视器（只读终端）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| M1 | 实时显示 agent 在每台主机上执行的命令、输出、退出码和耗时 | P0 |
| M2 | 按主机或 agent 会话分标签显示 | P0 |
| M3 | 回放历史会话；可以按命令跳转 | P1 |
| M4 | 标记由审批放行的命令，并显示审批人和审批时间 | P1 |

### 4.5 文件操作

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F1 | `read_file`：可以按行范围读取，返回内容和 `sha256` | P0 |
| F2 | `list_dir`、`search`：远程有 `rg` 时使用 `rg`，否则使用 `grep` | P0 |
| F3 | `apply_patch`：校验哈希、备份原文件、上传临时文件、原子替换，并保留权限和属主 | P0 |
| F4 | `write_file`、`upload`、`download` | P0 |
| F5 | 按任务回滚文件修改 | P1 |
| F6 | 桌面端远程文件浏览器和 diff 预览 | P2 |

### 4.6 端口映射（隧道）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| T1 | 本地转发（相当于 `ssh -L`）：本机端口 → 远程地址:端口 | P0 |
| T2 | 远程转发（相当于 `ssh -R`）：服务器端口 → 本机端口 | P1 |
| T3 | 动态转发 SOCKS5（相当于 `ssh -D`） | P2 |
| T4 | 显示隧道状态（已连接、断开、出错）、活跃连接数和收发流量 | P0 |
| T5 | 保存隧道配置；可以在守护进程启动时自动建立；断线后自动重连 | P0 |
| T6 | 检测本机端口冲突，冲突时推荐一个空闲端口 | P0 |
| T7 | 本机端口默认只绑定 `127.0.0.1`；绑定 `0.0.0.0` 前必须明确确认 | P0 |
| T8 | 一键在浏览器中打开或复制本地地址 | P0 |
| T9 | agent 可以调用 `tunnel_open`、`tunnel_list`、`tunnel_close`；agent 创建的临时隧道会在会话结束或超时后自动关闭 | P0 |
| T10 | 发现新的 web 端口时，提示用户一键转发 | P2 |

### 4.7 服务器端口管理（面向 web 服务）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| P1 | 通过 `ss -tlnp` 发现监听端口；没有 `ss` 时依次退回 `netstat`、`lsof` | P0 |
| P2 | 将端口关联到进程：PID、命令行、运行用户和启动时间 | P0 |
| P3 | 将端口关联到服务：systemd 单元、Docker 容器和端口映射，以及 docker-compose 项目 | P1 |
| P4 | 识别 web 服务：探测 HTTP/HTTPS，记录状态码、页面标题、`Server` 头和证书有效期 | P0 |
| P5 | 分析暴露面：结合绑定地址和防火墙状态（ufw、firewalld、nftables 或 iptables）判断服务是仅本机、内网还是公网可访问 | P1 |
| P6 | 解析 Nginx 和 Caddy 配置，显示“域名 → 上游端口”的对应关系 | P1 |
| P7 | 快捷操作：转发到本机并打开、查看日志（`journalctl` 或 `docker logs`）、重启或停止服务、结束进程；这些操作都需要经过策略检查 | P0 |
| P8 | 端口备注：可以为端口命名并关联项目 | P0 |
| P9 | 定时健康检查；服务异常时发送系统通知 | P1 |
| P10 | 部署辅助：检查端口是否被占用，并查找空闲端口 | P0 |
| P11 | 记录端口变化历史，包括新增、消失和进程变化 | P2 |
| P12 | 通过防火墙放行或关闭端口；该操作属于 L2 风险，必须审批 | P2 |

agent 侧对应的工具包括：`ports_list`、`port_inspect`、`port_check`、`port_find_free`、`service_logs` 和 `service_restart`。

### 4.8 策略与审批

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| S1 | 风险分级：L0 只读、L1 用户态修改、L2 系统变更、L3 破坏性操作；通过解析命令判断风险，并处理管道、`sh -c` 和 `sudo` | P0 |
| S2 | 可以按主机、环境标签、命令、路径和调用来源配置规则，决定允许、需要审批或拒绝 | P0 |
| S3 | 支持两种审批方式：阻塞等待（系统通知 + 桌面端弹窗）和异步审批（返回 `ticket_id`） | P0 |
| S4 | 审批界面显示主机、环境、完整命令或 diff、风险等级和调用来源；用户可以选择“本次允许”“本会话允许”或“总是允许” | P0 |
| S5 | 全局急停：一键暂停所有 agent 操作，并关闭 agent 创建的隧道 | P0 |
| S6 | 将服务器返回的日志和文件内容标记为不可信数据 | P1 |

### 4.9 审计

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| L1 | 记录每次调用的时间、来源、主机、操作、参数、结果和审批人 | P0 |
| L2 | 按主机、来源、风险等级和时间筛选；可以查看完整输出和 diff | P0 |
| L3 | 按任务或会话聚合成时间线 | P1 |
| L4 | 导出为 JSONL 或 CSV | P1 |

## 6. 非功能需求

- **安全**：本地 socket 只允许当前用户访问（macOS 和 Linux 使用 0600 权限，Windows 使用命名管道 ACL）；凭据不写入日志；审计记录只追加、不修改。
- **性能**：每台主机复用一条 SSH 连接；`exec` 的额外开销小于 50ms；守护进程空闲时内存占用目标低于 30MB；能同时支持 50 台主机和 100 条隧道。
- **可靠性**：守护进程崩溃后由系统服务自动拉起，并恢复已保存的隧道；后台任务不受断线影响。
- **兼容性**：服务器端只要求 POSIX shell 和 SFTP；缺少增强工具时自动降级。
- **跨平台**：支持 macOS、Windows 和 Linux。Windows 的命名管道支持在 V1 实现。
